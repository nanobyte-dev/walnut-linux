# PS3 tests: scheduled and done

The list of every PS3 test that is queued, and every batch that ran, so nothing built is forgotten
(the user, 2026-10-19). When a test is built or proposed it goes under Scheduled; when its batch
runs, it moves to History with the results commit. Rules: same-boot baselines, 60 s warm-up and a
120 s window, the picture checked (the screenshot sheets since 2026-10-20, the webcam before; the
webcam still for the TV and the sound), no commands on the PS3 during a run. New, untested
optimizations go on 2-3 games first; the rest of the suite follows once they hold up.

The console's internal disk is an upgraded SSD; a stock PS3 has a 2.5" HDD. Results on the SSD
root (`root=/dev/mapper/ps3root` in bench.txt) are better on disk-bound phases than a stock
console would see.

## Scheduled

### Played sessions: the Walnut Games round (the user plays both sides)

One game at a time: the PS3 is measured, the PC copy beside it is the picture and behaviour to
compare with ([GAMEDB.md](GAMEDB.md), SUITE.md "Played sessions"). `tools/play-test.sh start GAME
[LAUNCHER]` starts both (the PS3 session first: it counts the load), after the user's "go"; nothing
runs on the PS3 until the user says done; `tools/play-test.sh collect GAME` pulls and lists the
sessions, then the shots are looked at (REVIEW.md) and `import-run.py` files them. The game's settings
are the player's: never touched. A first start that only sets the game up (profile, video options)
is a session too, but isn't imported (first runs don't count for load).

Before the first game, once the PS3 is up in Walnut: `sudo apt-get update && sudo apt install
ps3-gpu-tools xmoto xmoto-data walnut-games` (the sound dropout logger, X-Moto's controller scheme,
the app's PS3-only screenshots), `make bench-push`, `tools/play-test.sh check`, then `ps3-xrun-test`
and `ps3-xrun-test -m` (a quiet tone on the TV for about 3 s each; both should end `ok: 4 dropouts
logged`).

The queue is each game's session items in GameDB (`gamedb/games/<id>/todo.toml`, kind `session`,
`order` its place), shown here with the game's medal now (from its played sessions); what else is
open for a game is in the same file. The table is generated (`tools/gamedb/blocks.py --write`):
edit the todo.toml, not the table.
