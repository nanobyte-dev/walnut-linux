# Backlog: the games

A game's own backlog lives in GameDB, in `gamedb/games/<id>/todo.toml` (an engine's in
`gamedb/engines/<e>/todo.toml`): its repeats and benchmarks, its package and engine fixes, what to
research, its place in the played-session queue. Each item says where it came from (`source`: a
PLAN item, a rank of [the ranked list](README.md), a TESTS.md table). What stays here is the work
the games found that isn't any one game's. Terms: [glossary](../README.md#glossary).

Effort: S = a day or less, M = days, L = weeks.

## Across the games

### Comments on a game's page

Players' comments on the site and in Walnut Games (a Community tab next to the PLAN 5.11 tabs). Parked by the user (2026-10-28). The idea so far: no database; a comment is a small submission through the receiver of the testers' CLI (walnut-rate, plan Part B), reviewed by the maintainer and committed as `gamedb/games/<id>/comments/*.toml`, which Hugo and the app both render. Works from the console without an account and keeps the site static; the cost is a delay until review. The other way, GitHub Discussions through giscus, needs a GitHub account and JavaScript (not NetSurf, not the console).

### OpenAL's stuck mixer: the sound card's DMA stops

Rank 72. In about 10% of OpenAL runs the sound stopped for the rest of the run.

**Why.** [LOG-FINDINGS.md, item 1](../games/LOG-FINDINGS.md#1-the-sound-cards-dma-stops-and-openals-mixer-waits-for-good):
snd_ps3's interrupt-driven DMA chain stops while the card stays RUNNING (dmix never lets it xrun), so
OpenAL Soft waits on dmix's period timer for good and logs `Wait timeout... buffer size too low?` once a
second ([SuperTuxKart](../../gamedb/games/supertuxkart/), [OpenArena](../../gamedb/games/openarena/), [ClassiCube](../../gamedb/games/classicube/), [Luanti](../../gamedb/games/luanti/)). Every OpenAL game's CPU number is lower in a
wedged run.

- **Fix.** Kernel patch local/0047 (snd_ps3 DMA watchdog, `snd_ps3.dma_watchdog_ms`). The harness
  records `snd_stall=`, `oal_wait=`, `oal_xrun=` and `snd_restarts=` in every run.
- **Payoff:** sound in four games (and any other game when the card stops); honest numbers.
- **Status:** proven with the test module in batch ssdroot12 (the off arm wedged 2 of 9 runs, the on arm
  0 of 9, fps equal); in the kernel since .648 (first booted 2026-10-21: a forced stall restarted, see
  [TESTS.md](../TESTS.md) "History").
- **Source:** logscan.py over 602 runs; the DUMPON captures of 2026-10-19.

### Mesa nv30 messages in the logs

Rank 74. Nothing in 602 runs reports a shader compile failure or a fallback, because Mesa is silent.

**Why.** [LOG-FINDINGS.md, "The tool"](../games/LOG-FINDINGS.md#the-tool): an "out of temps", TGSI or
draw-module fallback would cost fps without leaving a line. One run per game with `NV30_DEBUG` (or `MESA_DEBUG=1`, `GALLIUM_DEBUG`) into
game.log, then `logscan.py -c nouveau,gl`.

- **Payoff:** finds fallbacks we cannot see; upstream material. **Effort:** S. **Risk:** none.
- **Needs:** PS3. **Status:** scheduled: TESTS.md "Next".

### A Mesa default for the games we don't patch

Not ranked: measured, waiting for a default decision. Mesa's `NV30_SYSMEM_COPY=2` +
`NV30_INVALIDATE_BUFFER=1` on renderergl2's old 16-bit colours (`gl2min_color16`, batch 17): gameplay
stalls 11.1 to 1.4 s, swap stalls 22.9 to 0.9 s, 53.7 to 59.1 fps. [OpenArena](../../gamedb/games/openarena/)'s gl2min no longer needs
it ([ioquake3](../../gamedb/engines/ioquake3/) 0027 is the default), so the question is a default for the games nobody patched.

The per-game defaults that wait for a decision the same way ([ClassiCube](../../gamedb/games/classicube/) `CC_GL_CHUNKS=1`, [X-Moto](../../gamedb/games/xmoto/)
`XMOTO_GL_STREAM=1`, cube2 `vanormalshort 1`, ioquake3 `r_md3PackedFrames 1`) are `package` items in
their games' and engines' todo.toml.
