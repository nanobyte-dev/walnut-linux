# GL 3 census (2026-10-19): OpenMW (Morrowind)

Moved on 2026-10-26 from the GL 3 census, [gl3-census-f-engines.md](../../../research/gl3-census-f-engines.md) ("OpenMW (OpenSceneGraph, 0.51.0, git 2026-10-18 master)"), where the verdict, the FEATURES and the SCORES lines stay. What the census agent found on 2026-10-19: GL needs, the port, memory, CPU, big-endian, data, novelty, sources. Paths like `build/tmp/gl3census` and `$B` were the agent's scratch trees, deleted since.

### 1. GL needs (source + trace)
- Shaders are mandatory since 0.4x, but the `files/shaders/compatibility/` set is `#version 120` (40 files
  at version 120); `#version 330/430/440` appear only in `files/shaders/core/` (gui, compute) and
  `lib/core/*multiview*` (VR). `shadermanager.cpp:53-56` selects the root by prefix.
- Clustered lighting (SSBO, compute, GLSL 430) is off by default (`settings-default.cfg:486`,
  `clustered lighting = false`) and disabled with a warning below GLSL 430
  (`components/sceneutil/lightmanager.cpp:370-387`). Per-object uniforms are the fallback.
- Postprocessing is off by default (`settings-default.cfg:1283`, `[Post Processing] enabled = false`),
  shadows off (`:1027`), object paging on, distant terrain off, antialiasing 0, reflection detail 2.
  Postprocessing needs glDisablei for the normals buffer, RGB16F, and GLSL 330 for UBO state
  (`apps/openmw/mwrender/postprocessor.cpp:208-221, 490-495`); lacking them, the Fx techniques use GLSL 120
  (`components/fx/technique.cpp:87`).
- Reverse-Z needs ARB_clip_control; without it OpenMW logs a warning and uses a standard depth buffer
  (`components/sceneutil/depth.cpp:120-129`). Depth format list falls back to DEPTH24_STENCIL8 (`:153`).
- Measured trace, llvmpipe advertising 4.6 compat (30 s, menu/loading only, see section 3): GLSL 120 x10
  shaders, fixed-function matrix and client-array draws (glVertexPointer 60030 calls), UBO light blocks,
  glClipControl, DEPTH32F_STENCIL8, glTexStorage2D. These are the capability-gated paths.
- Measured trace with `MESA_GL_VERSION_OVERRIDE=2.1COMPAT`, `MESA_GLSL_VERSION_OVERRIDE=120` and the GL3
  extensions masked: OpenMW runs 30 s without crashing, logs "GL_ARB_clip_control not supported: disabling
  reverse-z", all 10 shaders stay `#version 120`, no UBO or float textures uploaded, DXT5 textures only
  (46 uploads, 12 MB). Caveat: with ARB_framebuffer_object masked OSG prints "EXT_framebuffer_object is not
  supported" twice (FBO path used for the GUI render-to-texture); on nv30 with real EXT FBO this needs a check.
  Two "invalid enumerant" GL errors in RenderBin::draw also appeared (UNVERIFIED which call; probably the
  masked-extension path).
- Not reached: a 3D world. The CC0 Template needs the OSG Collada plugin for `.dae` meshes; Debian's
  osgdb_dae failed ("Load failed in COLLADA DOM") and the Template ships no sky/creature `.nif` files, so
  New Game failed at `meshes/base_anim.nif`. So no draw-call or terrain numbers; only the GL capability path
  and a base RSS. Real Morrowind data would be needed (non-free).

### 2. Port to GL 2.1/GLES 2 on nv30
1:1 for the default configuration. Drop: postprocessing (off), shadows (off by default; the shadow shaders
use depth textures, which nv30 has, so they might work), water refraction/reflection depth (needs FBO +
depth copy, optional), clustered lighting (impossible), multiview. Per-pixel lighting loops over
`PointLightCount` lights (default max 8) with static bounds: the nv30 unroll should work but the
per-pixel object fragment shader may exceed 32 temps with normal maps and 8 lights; lower `max lights` to
4 and keep per-vertex lighting (the default: only normal-mapped objects use per-pixel). Driver-level help:
ARB_framebuffer_object in the 3.x override only matters for the optional paths. Effort L is almost all
the BE port and speed tuning, not the renderer.

### 3. Memory
Measured (Template + Example Suite "the hub", no world loaded, 1920x1080, llvmpipe, 60 s): peak RSS 456 MB
(VmHWM 491 MB); 2.1-override run 540 MB. That is the menu/loading state with 0 MB of world. The llvmpipe
baseline is ~107 MB, textures 12-27 MB: so the engine itself is ~300 MB before any cell loads (Lua,
Bullet, navmesh thread, OSG, MyGUI, fonts, 100+ shaders compiled). Real Morrowind exteriors are reported
at 1-2 GB RSS (UNVERIFIED, from community memory). Cuts: disable the navigator (`[Navigator] enable = false`),
view distance 3000-4000, object paging min size up, no distant terrain, texture mip skipping (no setting,
would be a patch: Morrowind textures are mostly 256-512 px), DXT at upload via NV30_FORCE_DXT. Original
Morrowind ran on a 64 MB Xbox, so content fits; the engine does not. Estimate: 500-800 MB after cuts.
Playability 2 (swap-bound).

### 4. CPU
OSG cull and draw traversals on the main thread: one GL draw per object (no instancing), ~25-45 draws per
frame in the menu trace but thousands in a Seyda Neen-class exterior (UNVERIFIED). Physics (Bullet) in 1-N
async threads (log: "Using 1 async physics threads"), navmesh in a background thread, Lua scripting (0.49+)
global and local scripts each frame. The Mesa nv30 driver cost of 30-55% PPE applies. Measured on PC:
openmw main thread 7-9.6 CPU s in 30-60 s (mostly loading). Interiors plausible at 30 fps, exteriors
likely under 20 fps without paging and light cuts. Estimate only.

### 5. ppc64 big-endian
- Debian-ports ppc64 and s390x both build 0.51.0-1+b4 (buildd.debian.org), but building is not running.
- `components/nif/nifstream.hpp:36-70` byte-swaps NIF buffers when `Misc::IS_BIG_ENDIAN`;
  `components/misc/endianness.hpp`, `serialization/binaryreader.hpp`, `bgsm/stream.hpp` and the Lua
  serializer also swap. So meshes should load.
- ESM: `components/esm3/esmreader.hpp:317` `getT` is `mEsm->read(&x, sizeof(X))` with no swap, and every
  record funnels through it (213 getHT/getHNT/getHNOT uses in esm3, plus decompose-based composites).
  Because `getT` takes only arithmetic, enum and arrays of them (`IsReadable`, `:45`), one byte-swap in
  `getT`, `getExact` users (raw arrays like LAND heights) and the ESM writer fixes most of it.
- BSA: `components/bsa/*.cpp` use `in.read(reinterpret_cast<char*>(&x), sizeof)` with no swap (ba2dx10file.cpp
  :32-57 and the BSA header/offset reads). Needs swaps in bsafile.cpp.
- Also check: OSG's DDS/TGA readers (Debian OSG; DDS has explicit BE handling in OSG, UNVERIFIED), esm4,
  save files (ESM writer), the sqlite navmesh cache (LE structs, drop the cache).
- BE work: M (ESM getT, BSA, ESM writer, test with a real ESM on the PS3), but real validation needs
  Morrowind.esm (non-free) because the Example Suite is a tiny content set.

### 6. Data and licence
Engine GPL-3. Morrowind data non-free (GOG/Steam, ~1 GB BSAs). Free: OpenMW Template (CC0) + Example Suite
"the hub" at gitlab.com/OpenMW/example-suite (CC0, MyGUI configs GPL-3), 135 MB + 24 MB data. The suite is
a small showcase, not a game.

### 7. Novelty
No PS3 GameOS Morrowind or OpenMW port found (web search, 2026-10-19). PS3 had Oblivion and Skyrim only.
OpenMW has no console port that I could confirm.
