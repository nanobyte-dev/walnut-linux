# github-ci/: what GitHub Actions runs: building one package (`build-package.sh`), testing's one publisher (`batch-publish.py`: every build testing lacks, from the package runs' artifacts, in one upload), `publish.sh` (the upload to testing or stable and the server's verdict), the release image, and `gen-workflows.py`, which writes `.github/workflows/pkg-<name>.yml` and `walnut-publish.yml`.
Run `python3 github-ci/gen-workflows.py` after adding, moving or removing a package; licensed packages never get a workflow.
Touch it when CI's build or publish steps change (docs/PACKAGING.md "Walnut's suites on GitHub Actions", docs/release/ALPHA.md M6). `packages.toml` lists the binary names each package owns (and its trust tier and allowed relations), `walnut_lists.py` reads it, `protected-names.txt` names the Debian packages no build may replace or provide. The publisher checks every build against it (verify job without secrets, then the publish job); `build-package.sh` runs the same check as a drift check. Tests: `test_batch_publish.py`, `test_walnut_lists.py` (in `make test`).
